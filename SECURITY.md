# Защита Tutorina

## Модель данных

Приложение хранит административные логины, хеши паролей, сессии и расписание.
В расписании нет участников, имён и контактов. Заявки, профили преподавателей,
фотографии и прикладное шифрование персональных полей удалены из кода и схемы.
Для логинов используйте технические обозначения, для направлений — общие названия
занятий. Свободные текстовые поля не должны содержать персональные сведения.

## Реализовано

- Изменения слотов доступны только авторизованному администратору.
- Публичный API выдаёт только свободные будущие опубликованные слоты.
- Вместимость и занятость проверяются в API и ограничениями PostgreSQL.
- Пароли хранятся как bcrypt-хеши; токены сессий — как SHA-256-хеши.
- Сессии используют `HttpOnly`, `SameSite=Strict` cookie; смена пароля завершает сессии.
- PostgreSQL и backend не публикуют порты наружу в Compose.
- HTTP-запросы имеют ограничения размера тела и таймауты.

## Перед размещением

- Настроить домен, HTTPS и `AUTH_COOKIE_SECURE=true`.
- Задать сильные пароли БД и администратора; хранить секреты вне Git.
- Настроить firewall и доступ к серверу по SSH-ключам.
- Разделить роли PostgreSQL для миграций и работы приложения.
- Настроить резервное копирование и проверить восстановление.
- Ограничить частоту попыток входа на сервере или прокси.
- Настроить срок хранения инфраструктурных логов и регулярно обновлять зависимости.

Новая схема применяется к пустой БД. Старые локальные тома, резервные копии,
фотографии и файлы ключей не подключаются новой конфигурацией; смена кода не
означает их автоматическое удаление.
