# Tutorina

Публичная доска свободных слотов и закрытая админка расписания. Посетители только
смотрят доступное время. Создание, перенос, отмена, публикация и учёт занятых мест
выполняются администратором. Заявки, участники, контакты, профили преподавателей и
фотографии не хранятся. Общение происходит вне сайта.

## Запуск

```bash
cp .env.example .env
docker compose up --build -d
```

Доска: <http://localhost:18080/>, вход: <http://localhost:18080/login>,
админка: <http://localhost:18080/admin>.

Создание администратора:

```bash
BOOTSTRAP_USERNAME=admin \
BOOTSTRAP_PASSWORD='replace-with-a-long-password' \
docker compose --profile tools run --rm create-user
```

Логин — от 3 до 64 латинских букв, цифр, `_` или `-`, без персонального имени
или email. Логин приводится к нижнему регистру. Пароль — не менее 12 символов
и не более 72 байт (ограничение bcrypt). Смена пароля доступна в админке и
завершает все сессии. Сессии передаются через `HttpOnly`, `SameSite=Strict` cookie.
Для локального HTTP используется `AUTH_COOKIE_SECURE=false`.

## Расписание

Слот содержит направление, время начала и окончания, формат (онлайн/очно),
тип (индивидуально/группа), вместимость, число занятых мест, статус и признак
публикации. Индивидуальный слот имеет одно место. Для группы вместимость — от
1 до 1000; занятость — от нуля до вместимости. Ограничения проверяются API и БД.

Публичная доска показывает только опубликованные будущие слоты в статусе
«Запланирован» с хотя бы одним свободным местом. Заполненные, скрытые,
отменённые и завершённые слоты остаются в админке. Время в интерфейсе и редакторе
указывается по Москве (`Europe/Moscow`), в API — RFC 3339 с часовым поясом.

Направление — общее название занятия, например «Математика». Не используйте
это поле для имён, контактов или персональных заметок.

## API

Все адреса ниже имеют префикс `/api/v1`:

- `GET /slots` — свободные слоты и число свободных мест;
- `GET|POST /admin/slots/` — полное расписание и создание слота;
- `PUT|DELETE /admin/slots/{id}` — изменение и удаление слота;
- `POST /auth/sessions` — вход с `username` и `password`;
- `GET /auth/me` — текущая административная учётная запись;
- `PUT /auth/password` — смена пароля;
- `DELETE /auth/session` — выход;
- `GET /ping` — доступность БД.

Данные слотов возвращаются в `{ "data": ... }`. Публичные запросы на изменение
слотов отсутствуют. Старые маршруты школы удалены.

## Новая база данных

Старые миграции заменены одной начальной схемой. Она предназначена для пустой
БД, а не для обновления старой схемы. Compose использует новый том `schedule_data`,
поэтому ранее созданный `postgres_data` не подключается и не удаляется автоматически.
Ранее созданные локальные данные и файлы ключей приложению больше не нужны.
Не запускайте новую миграцию на старой БД при разработке без Docker.

PostgreSQL хранится в именованном томе. `docker compose down` сохраняет данные;
`docker compose down --volumes` удаляет тома текущей конфигурации, включая новое
расписание. Наружу опубликован только Caddy на порту `18080`.

## Разработка и проверки

Backend: Go, chi, PostgreSQL, Goose. Frontend: React, TypeScript, Vite, Material UI.

Для разработки без Docker настройте пустую локальную БД и переменные из `.env.example`
(включая `DB_HOST=localhost`, `AUTH_COOKIE_SECURE=false`), затем:

```bash
cd backend
go run ./cmd/migrate
go run ./cmd/user -username admin -roles admin # BOOTSTRAP_PASSWORD в окружении
go run ./cmd/api
```

Frontend (Vite проксирует `/api` на порт `8081`):

```bash
cd frontend
npm ci
npm run dev
```

Проверки:

```bash
cd backend && go test ./...
cd frontend && npm run lint && npm run build
docker compose config --quiet
```
