# Tutorina

Публичная доска свободных слотов и закрытая админка расписания. Посетители только
смотрят доступное время. Создание, перенос, отмена, публикация и учёт занятых мест
выполняются администратором. Заявки, участники, контакты, профили преподавателей и
фотографии не хранятся. Общение происходит вне сайта.

## Запуск

```bash
cp .env.example .env
docker compose up --build -d
```

Доска: <http://localhost:18080/>, вход: <http://localhost:18080/login>,
админка: <http://localhost:18080/admin>.

Создание или замена ключа доступа:

```bash
docker compose exec -T backend ./tutorina-key
```

Команда выдаёт один случайный ключ: 64 строчных шестнадцатеричных символа
(256 бит случайности). Сохраните его и введите в единственное поле на странице
входа. В БД хранится только SHA-256-хеш ключа; исходный ключ не сохраняется
приложением. Пока ключ не создан, публичная доска доступна, а вход закрыт.

Каждый повторный запуск команды заменяет ключ и завершает все существующие
сессии. Если ключ потерян, создайте новый этой же командой. Генерация также
доступна через `docker compose --profile tools run --rm create-key`.

После входа временный токен хранится в sessionStorage текущей вкладки.
Обновление страницы сохраняет вход; после закрытия вкладки нужно снова ввести ключ.
Сам ключ не сохраняется. Сервер ограничивает срок сессии через AUTH_SESSION_TTL.
Браузер может восстановить sessionStorage при восстановлении закрытых вкладок.
При размещении приложения используйте HTTPS.

## Расписание

Слот содержит направление из справочника, необязательный уровень занятия,
время начала и окончания, формат (онлайн/очно),
тип (индивидуально/группа), вместимость, число занятых мест, статус и признак
публикации. Индивидуальный слот имеет одно место. Для группы вместимость — от
1 до 1000; занятость — от нуля до вместимости. Ограничения проверяются API и БД.

Публичная доска показывает только опубликованные будущие слоты в статусе
«Запланирован» с хотя бы одним свободным местом. Заполненные, скрытые,
отменённые и завершённые слоты остаются в админке.

Расписание оформлено как школьная таблица: дни недели по колонкам, время
начала по строкам. Занятия с одинаковым временем в один день показываются
в одной ячейке отдельными карточками. Можно переключать недели, возвращаться
к сегодняшней дате и переходить к ближайшему занятию. На телефоне доступен
просмотр одного дня с переключением дней недели. Админка показывает все статусы
и кнопки изменения и удаления; посетителям видны только свободные слоты.

Время в интерфейсе и редакторе указывается по Москве (`Europe/Moscow`), в API — RFC 3339 с часовым поясом.

Направления добавляются, переименовываются и удаляются в админке по адресу
`/admin/directions`. При создании слота направление выбирается из списка.
Название уникально без учёта регистра и пробелов по краям. Направление,
используемое хотя бы одним слотом, удалить нельзя; переименование обновляет
название во всех связанных слотах.

Уровень — необязательное поле до 80 символов, например «Начальный», «A2» или
«7 класс». Он показывается в админке и на публичной доске; поиск на доске
учитывает направление и уровень. Направление — общее название занятия,
например «Математика». Не используйте эти поля для имён, контактов или
персональных заметок.

## API

Все адреса ниже имеют префикс `/api/v1`:

- `GET|POST /admin/directions/` — список и создание направлений;
- `PUT|DELETE /admin/directions/{id}` — переименование и удаление направления;
- `GET /slots` — свободные слоты и число свободных мест;
- `GET|POST /admin/slots/` — полное расписание и создание слота;
- `PUT|DELETE /admin/slots/{id}` — изменение и удаление слота;
- `POST /auth/sessions` — вход с `{ "key": "..." }`;
- `GET /auth/session` — проверка текущей сессии (204 при успешной проверке);
- `DELETE /auth/session` — выход;
- `GET /ping` — доступность БД.

При создании и изменении слота передаются `directionId` и необязательный
`level` (пустая строка означает отсутствие уровня). Поле `title` возвращается
из справочника и отдельно не задаётся.

Данные слотов возвращаются в `{ "data": ... }`. Публичные запросы на изменение
слотов отсутствуют. Старые маршруты школы удалены.

## Новая база данных

Начальная схема содержит ключ доступа, сессии и слоты. Миграция
`00002_directions_and_level.sql` создаёт справочник, переносит названия
существующих слотов в направления и добавляет уровень без удаления расписания. Она предназначена для пустой
БД, а не для обновления старой схемы. Compose использует новый том `schedule_data`,
поэтому ранее созданный `postgres_data` не подключается и не удаляется автоматически.
Старая схема с пользователями и ролями несовместима с новой авторизацией.
Для ранее созданной локальной БД нужна новая пустая схема или отдельная замена
таблиц авторизации с сохранением slots.
Не запускайте новую миграцию на старой БД при разработке без Docker.

PostgreSQL хранится в именованном томе. `docker compose down` сохраняет данные;
`docker compose down --volumes` удаляет тома текущей конфигурации, включая новое
расписание. Наружу опубликован только Caddy на порту `18080`.

## Разработка и проверки

Backend: Go, chi, PostgreSQL, Goose. Frontend: React, TypeScript, Vite, Material UI.

Для разработки без Docker настройте пустую локальную БД и переменные из `.env.example`
(включая `DB_HOST=localhost`), затем:

```bash
cd backend
go run ./cmd/migrate
go run ./cmd/key # выдаёт новый ключ, заменяет прежний и завершает сессии
go run ./cmd/api
```

Frontend (Vite проксирует `/api` на порт `8081`):

```bash
cd frontend
npm ci
npm run dev
```

Проверки:

```bash
cd backend && go test ./...
cd frontend && npm run lint && npm run build
docker compose config --quiet
```
